Relationships

Entity Relationships
users ──→ teams (manager_id) — one team manager has many users
leads ──→ users (owner_id) — one owner, many leads
leads ──→ opportunities (lead_id) — one lead → one active opp
contacts ──→ leads (company_id) — contacts belong to a lead/company
contacts ──→ opportunities (opp_id) — contacts linked to a deal
opportunities ──→ users (owner_id) — one owner, many opps
tasks ──→ opportunities (opp_id) — tasks belong to a deal
tasks ──→ users (assigned_to) — tasks assigned to user
emails ──→ opportunities (opp_id) — email linked to deal
emails ──→ users (sender_id) — sender
audit_log ──→ users (actor_id) — who did it

Row-Level Security ( enforced at DB level )

user_id filter is applied via a getAccessibleRecords(query, user_id) function. All tools call this before any SELECT.
Permission Matrix
admin — can see all records in their team
manager — can see own + reports' records
sales — can see only owner_id = current_user.id
All users: cannot see lost_reason of other users' opportunities unless manager+
